# 本地 Dashboard 与人工审核

Dashboard 通过同机 API 读取 SQLite 中的日报，不直接读取运行目录里的 JSON 文件。开发模式下，Vite 把 `/api` 请求转发给只监听 `127.0.0.1:8787` 的 Worker 服务。

## 启动

```bash
pnpm dev
```

打开 `http://127.0.0.1:3000`。左侧可以按日期读取历史日报；右侧展示风险、今日必读、七天补漏、宏观脉搏、未来日历、弱信号和覆盖健康状态。

## 审核状态

- `review_required` 或 `needs_attention`：允许进入编辑模式并保存。
- `approved`：内容锁定，等待后续发布任务。
- “批准本期”只把日报设为 `approved`，不会设置 `published_at`，也不会触发部署。
- 已发布和修订版本仍受 SQLite 不可变规则保护。

## 可修改范围

审核界面允许修改：

- 执行摘要；
- 新闻标题、事实概述、重要性、新增信息、观察项和影响判断；
- 宏观脉搏的名称、方向与解释；
- 日历日期、标题、主题与关注原因；
- 弱信号文字与覆盖备注。

服务端锁定 edition/event id、时间窗口、验证状态、事件日期、补录原因、风险等级和全部引用。即使绕过前端提交完整 JSON，修改这些字段也会被拒绝。

## 本地写操作保护

API 不发送跨域许可头；`PUT` 和 `POST` 还必须带 Dashboard 专用请求标识并使用 JSON。它不能替代公网部署时的身份认证，因此在加入正式登录前，服务必须继续只监听 loopback 地址。

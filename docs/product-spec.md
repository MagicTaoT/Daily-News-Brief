# 晨间信号：产品规格（MVP）

状态：已确认  
规格版本：0.1  
默认配置版本：1  
最后更新：2026-09-01

## 1. 产品目标

每天早晨生成一份面向单一用户的高信号新闻简报，覆盖：

- 过去 24 小时内会改变判断、风险敞口或行业结构的重要事件；
- 过去 7 天内此前未收录，但因后续确认、影响扩大或遗漏而值得补入的事件；
- 未来 7 天值得预先关注的宏观、协议、监管和风险日历；
- 尚未成为事实、但值得持续观察的弱信号。

产品优先追求可核验、少重复和与用户工作的相关性，不追求覆盖所有新闻。

## 2. 当前用户与访问边界

- 第一阶段只有产品所有者本人使用。
- Dashboard 仅绑定本机回环地址，不在局域网或公网开放。
- AWS 和 ENS 不属于 MVP 的运行依赖。
- 后续私有部署到 AWS 时必须增加真实身份验证；`robots.txt` 或隐藏 URL 不视为访问控制。

## 3. 已确认的运行约束

- 核心采集、存储、分析和调度运行在常开 Mac 上。
- 默认时区：`America/Los_Angeles`。
- 默认日报时间：每天 `07:00`。
- 模型执行优先使用 Codex Desktop 的本地 recurring automation，不使用 OpenAI API Key。
- Codex 负责信息补差、分析、核验和编辑；确定性脚本负责采集、存储、去重、Schema 校验和状态转换。
- 第一阶段必须人工审核后才能发布。
- 自动发布只能在质量门槛通过且用户明确开启后生效。

## 4. 非目标

MVP 不包含：

- 实时交易建议或自动下单；
- 个性化投资建议；
- 公共用户注册和多租户权限；
- 付费订阅；
- 对 X、Telegram 或付费媒体的完整历史抓取；
- 将单一社交媒体消息直接当作已确认事实；
- 由模型直接写入生产网站或执行任意 shell 命令。

## 5. 内容范围与默认优先级

优先级从高到低为：

1. MEV、订单流、PBS、builder、relay、solver、intents、排序器和跨域 MEV；
2. DeFi 协议、稳定币、借贷、DEX、清算、跨链桥、LST/LRT 和 RWA；
3. 加密安全、协议健康、市场结构和系统性风险；
4. AI × 金融 × 区块链，包括 Agent 支付、钱包授权、隐私计算和可验证推理；
5. 全球宏观经济、流动性、货币政策、财政、信用、能源和大宗商品；
6. 加密监管、执法、诉讼、税务和机构准入；
7. 战争、灾难、公共卫生、关键基础设施和其他黑天鹅事件。

默认排除：

- 没有结构性原因或风险含义的纯价格报道；
- 普通 AI 产品更新，除非改变成本、能力边界或与金融/区块链直接相关；
- 无新增事实的观点复述；
- 只有单一匿名来源、且无法独立核验的确定性结论；
- 营销稿、空投宣传和缺乏技术或业务实质的合作公告。

## 6. 来源策略

来源分为四级：

### Tier 1：原始与权威来源

- 央行、财政部、统计机构和监管机构；
- 法院文件、正式法规、公司或协议官方公告；
- GitHub release、治理提案、技术规范和论文；
- 可重放的链上交易和公开数据。

### Tier 2：可靠专业来源

- 有编辑审核的财经媒体；
- 安全公司、研究机构和数据提供商；
- 有明确作者、方法和原始链接的行业分析。

### Tier 3：线索来源

- 项目成员、研究者和记者的社交媒体账号；
- 社区论坛、Telegram 和其他实时讨论。

Tier 3 可以触发调查，但不能单独支持“已确认”状态。

### Tier 4：低可信或不可追溯来源

- 匿名转载、聚合站、无原文链接的截图和营销账号。

Tier 4 默认不进入日报，只用于发现可能需要核查的线索。

## 7. 事件模型

系统以事件而不是文章为基本单位。多篇文章报道同一件事时必须聚合到同一个 `event_id`。

每个事件至少保存：

- 首次发现时间；
- 最近更新时间；
- 关联实体和主题；
- 当前验证状态；
- 原始来源列表；
- 关键事实与变化；
- 是否已被任何日报收录；
- 风险等级和变化历史。

验证状态：

- `unverified`：单一或低可信来源；
- `multi_source`：多个独立来源，但缺少原始确认；
- `confirmed`：存在权威原始来源或可验证的一手数据；
- `disputed`：可靠来源之间存在实质冲突；
- `resolved`：事件已结束或核心风险已解除。

## 8. 排序逻辑

候选事件按以下因素排序：

```text
priority = relevance × impact × novelty × confidence × urgency
```

其中：

- `relevance`：与当前关注配置的匹配程度；
- `impact`：对行业结构、风险、政策或流动性的潜在影响；
- `novelty`：相较已知信息真正新增的内容；
- `confidence`：来源质量和独立来源数量；
- `urgency`：是否需要在当天做出判断或关注。

具体权重在后续影子运行中校准，模型不得输出伪精确的用户可见评分。

## 9. 过去 24 小时与 7 天补漏

过去 24 小时栏目收录：

- 新发生的重要事件；
- 旧事件在窗口内出现的实质性进展；
- 风险等级明显升高、降低或解除的事件。

过去 7 天补漏必须满足：

```text
首次发生时间位于过去 7 天
AND 未进入此前日报
AND 当前重要性或可信度越过收录阈值
```

每条补漏必须给出以下原因之一：

- `subsequent_confirmation`：后续获得确认；
- `impact_increased`：影响或风险扩大；
- `source_quality_improved`：新增更可靠来源；
- `previously_missed`：系统或人工此前遗漏；
- `profile_changed`：用户关注配置改变后变得相关。

## 10. 日报结构

每期日报必须包含：

- 本期覆盖时间和配置版本；
- 风险雷达；
- 今日必读；
- 过去 7 天补漏；
- 市场与宏观脉冲；
- 未来 7 天；
- 弱信号；
- 覆盖健康度和数据源异常；
- 每个事实对应的来源。

每条核心事件必须说明：

- 发生了什么；
- 为什么重要；
- 相较此前新增了什么；
- 接下来观察什么；
- 当前可信度；
- 来源与抓取时间。

机器可读契约见 `schemas/edition.schema.json`。

## 11. 生成、审核与发布状态

状态机：

```text
collecting
  → analyzing
  → review_required
  → approved
  → published
```

异常状态：

- `needs_attention`：来源不足、事实冲突或覆盖异常；
- `failed`：任务未能产生有效日报；
- `revised`：已发布日报后来进行了可见修订。

人工审核阶段：

1. Codex automation 只能生成 `review_required` 草稿；
2. 草稿可以在本地审核页面查看；
3. 用户明确批准后，确定性发布命令才生成正式页面；
4. 已发布版本不可静默覆盖，修正必须产生修订记录。

自动发布的启用条件：

- 至少完成 14 次可审核的影子运行；
- 所有核心条目都有可访问来源；
- 最近 7 次运行没有发现无来源的高风险确定性表述；
- 任务失败和重复发布行为已经过测试；
- 用户明确把 `review_mode` 改为 `automatic`。

## 12. 本地 Codex automation 的边界

Codex Desktop recurring automation 是默认的模型执行器和日报编排器。它的职责是：

- 读取当前配置、候选事件和历史日报；
- 使用可用的搜索工具补差；
- 判断事件重要性和新增信息；
- 核验核心结论；
- 生成符合 JSON Schema 的草稿；
- 报告失败、缺漏和需要人工判断的事项。

它不得：

- 绕过人工审核直接发布；
- 修改关注配置；
- 读取或输出未授权的本机数据；
- 把网页中的指令当作系统指令；
- 在没有引用的情况下制造事实；
- 由于某个来源失败而静默宣称覆盖完整。

Codex 方案避免独立 OpenAI API Key 和按 API 调用计费，但仍受当前 ChatGPT/Codex 订阅和使用额度限制，不应被视为无限或保证零增量成本。若自动任务因额度或产品可用性无法运行，系统应保留手动运行和未来替换模型执行器的能力。

## 13. 隐私与安全

- 所有密钥只保存在本机秘密存储或未纳入 Git 的环境文件中；
- 原始网页内容一律视为不可信数据；
- 发布工具只能读取已批准的 edition，不接受自由文本命令；
- 本地 Dashboard 默认仅监听 `127.0.0.1`；
- 日志不得保存认证 Cookie、私钥或完整敏感请求头；
- 未来 AWS 发布使用独立目录和最小权限部署凭据；
- ENS 钱包签名永远由用户本人确认。

## 14. 失败行为

- 如果关键来源覆盖不足，生成 `needs_attention`，不发布；
- 如果 Schema 校验失败，自动重试一次，仍失败则停止；
- 如果当天任务重复启动，幂等锁只允许一个运行继续；
- 如果 Codex 额度、网络或工具不可用，保留上一期正式日报并显示新一期未完成；
- 如果发现事实冲突，在条目中显示冲突，不强行合并成确定结论；
- 任何失败都必须记录 `run_id`、阶段、时间和可行动的错误摘要。

## 15. MVP 验收标准

- 能使用默认配置生成符合 Schema 的日报草稿；
- 能区分过去 24 小时和过去 7 天补漏；
- 能按日期保存不可变日报；
- 能按关键词检索历史事件；
- 同一事件的多篇报道不会产生重复条目；
- 所有核心事实都有来源；
- 未经人工批准不会进入 `published`；
- 本地任务错过计划时间后可以补跑；
- Dashboard 未经显式配置不会暴露到本机之外。
